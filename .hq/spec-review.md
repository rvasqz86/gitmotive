## Round 1 — spec review
- [blocker] spec "Demo data" + tasks 05/11/21 — The dogfood capture for this repo runs from the user-scope hooks in `~/.claude/settings.json`, which execute the old installed copy (`~/.gitmotive/venv/.../site-packages`), not this branch. Events captured while building the branch will never carry `agent`/`model` (today's store for this repo, `~/.gitmotive/repos/0663563df78ac40a/events.jsonl`, has 13 events and no `model` key), so the demo cannot show the model, which the brief requires on click. — Add a step right after task 05 (manager or a human action listed in Open questions) that reinstalls the venv from the branch (`sh install.sh`) or points the hooks at the working tree. Task 21 must also accept that pre-05 events have no model, and its acceptance criteria should require at least one match per default file with a non-null `model`.
- [blocker] spec "Audit scanner"/"Denylist handling" + tasks 02/04/11/18/21 — No suppression mechanism exists. `--tree` must exit 0 (tasks 04, 18, 21), but the tree will contain planted test secrets (`tests/test_audit.py`: AKIA key, `ghp_` token, a private 10/8 test address) and the scanner's own literal patterns (`sk-ant-`, `github_pat_` match themselves). The exporter gate has the same problem: the current dogfood store already contains `AKIA`, `sk-ant-` and `192.168.` (from planner edits of the spec), and task 21 even adds `scripts/audit_public.py` to the exported files. — Specify one rule: test fixtures build secrets by string concatenation at runtime, and the scanner builds its literal prefixes the same way. Optionally add a committed `.audit-allow` (path + check id, no secrets) whose entries report as `info`. Separately, state which exporter strings are gated (emitted fields only).
- [major] spec "Demo data" + task 11 — Abort-on-any-hit across the whole export means one bad prompt blocks the core deliverable, and the store already has gate-tripping text. — Make the gate per record: drop the prompt/match (or replace its text with `[omitted: <check>]`), count the drops on stderr, and exit 1 only if a hit survives into the output file. Keep the test that the term never appears in output.
- [major] spec "Demo data" + task 11 — `--rev` is not implementable as written. `resolve.find` blames the working tree and reads line text from disk (`resolve.line_text` opens `root/file`), so "reads the file at `--rev`" disagrees with its `find` call. Two engineers would ship different things. — Either restrict to `--rev HEAD` with a clean-tree check (abort if the listed files are dirty), or add a `rev` parameter to `resolve.blame_line`/`line_text` as a scoped change with tests.
- [major] spec "Demo data" + task 11 — The exporter calls `cli._stamp`, which calls `store.rewrite_all` and rewrites the developer's real dogfood store as a side effect of generating site data. — Call `_stamp` on a copy without persisting (e.g. pass a flag, or reimplement stamping in memory), or state explicitly that it mutates the store, and test that with a temp `GITMOTIVE_HOME`.
- [major] spec "Demo data" schema — It does not say whether `prompts` holds every prompt in the store or only those referenced by an exported `match`. Unreferenced prompts are unnecessary exposure: the store has orchestrator prompts with `pasted_content` and the literal strings `gitmotive blame`/`gitmotive init` (2 each), which would then fail `test_public_text.py` if it scans `site/demo/data.json`. — Export only prompts referenced by a match. State whether `test_public_text.py` scans `data.json`; recommended: exclude it from the command check and rely on the exporter gate plus the audit.
- [major] spec "Capture: agent and model" + task 05 — `install_omp` and `install_copilot` (alias mode) both write `--agent claude` into the hook command, so `normalize` resolves `agent="claude"` and the documented values `"copilot"`/`"omp"` are never produced. Events from those agents would be mislabelled as Claude in `why` and the demo. — Add a separate label arg, e.g. `--source omp|copilot`, written by those installers, which sets `agent` while still using the claude payload shape. Or document that `agent` means payload shape, not product. Add a test for each installer's resulting `agent`.
- [major] task 08 — Combining `license = "MIT"` (SPDX expression, already in pyproject) with the mandated classifier `License :: OSI Approved :: MIT License` fails the build on setuptools ≥ 77 (local setuptools is 75.8.0, but isolated builds pull the latest). On setuptools < 77, `license = "MIT"` plus `license-files` may itself be rejected under `--no-isolation`. — Drop the License classifier and raise `build-system.requires` to `setuptools>=77`. Have `test_packaging.py` skip the `--no-isolation` build when the installed setuptools is < 77 rather than fail.
- [major] task 15 / spec "Deploy" / task 17 — Cloudflare Pages `_redirects` does not support status 404 (only 301/302/303/307/308 and 200 proxying), so `/DEMO_SCRIPT.md /404.html 404` will not block the file, and task 17 would report a false "blocked" state.
