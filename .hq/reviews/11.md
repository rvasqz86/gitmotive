## Round 1 — code review
- [major] site/index.html:56,60,83,117 and site/404.html:36 — the focusable `<pre tabindex="0" aria-label="…">` scroll regions have no role. `pre` maps to the generic role, where ARIA 1.2 prohibits `aria-label`. Screen readers drop the name, so focus lands on an unnamed stop, and axe reports `aria-prohibited-attr` (serious). This undercuts the spec's accessibility requirement. — Add `role="region"` (or `role="group"`) to each of these `pre` elements so the label is exposed. Add a check in `markup_problems` that fails `aria-label` on `pre`/`div`/`span` with no role, and give it a self-test.
- [minor] site/index.html:60-71 — the implementation notes say the intent panel "uses the real `cmd_why` output format", but it doesn't. Real output (gitmotive/cli.py:79-114) starts with `src/fetch.py:42` and `  | <line text>`, indents the fields by 2 spaces, puts `[<match reason>]` on the `edited` line before `via`/`model` (both on that same line), and indents siblings by 4. — Either match the real output (`src/fetch.py:42`, `  |             time.sleep(2 ** attempt)`, `  commit   …`, `  edited   … [why]  via claude  model …`) or drop the claim. Visitors will compare this panel with the demo and their own terminal.
- [minor] site/assets/site.css:303-304 — `.steps { list-style: none }` on the `<ol>` makes Safari/VoiceOver drop list semantics, so the "real sequence" is no longer announced as a 3-item list. — Add `role="list"` to `<ol class="steps">` (the order stays clear from the `counter(step)` text).
- [minor] site/404.html:11-15 — the 404 page sets `og:url` to the home URL along with og/twitter tags. That is harmless (it's `noindex`) but misleading if someone shares a dead link. — Drop the og/twitter block on 404, or leave it; this doesn't block.
- [minor] site/index.html:139-143 — design: the three-up "Deterministic / Local / Open source" fact grid is the one template-looking pattern on an otherwise distinctive page. The diff-hunk tagline, blame gutter + intent split, struck-through "lost context" diff, `#` headings and `±` mark are all strong and on-brand. — Optional: render the facts as a terminal-style key/value list like the intent panel, or leave them.
