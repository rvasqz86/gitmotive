- [minor] site/demo/viewer.css:103 — `.meta { display: flex }` overrides the `hidden` attribute (there is no `.meta[hidden]` rule, unlike `.state`, `.viewer` and `.keys`), so the empty `#meta` paragraph still takes up space while loading and in the error state — add `.meta[hidden] { display: none; }`.
- [minor] site/demo/viewer.js:460-476 — anything that throws after the fetch try/catch (a null line entry in renderFile `l.n`, or a non-iterable `f.lines` at line 468) is an unhandled rejection that leaves the page stuck on "loading data.json" with no error state — wrap the render phase in try/catch and call `showError("unreadable data")`.
- [minor] site/demo/viewer.js:296 — a matched line where both `m.commit` and `l.commit` are null renders an empty gutter, but the spec says the gutter shows a short SHA or `·` — fall back to a marker (for example `·` or `+`) so the gutter is never blank.
- [minor] site/demo/viewer.js:234 / index.html:50 — the error is announced through `role="status"` (polite). Also, clicking "Try again" removes the focused button, so focus drops to `<body>` — use `role="alert"` for the error state, or move focus to the state box after a retry.
- [minor] site/demo/viewer.js:244 — in the empty-data banner, an export whose files all have zero lines reads "0 of 0 lines" followed by "Every line below still has its blame", which is wrong because there are no lines — word the banner differently when `totalLines === 0`.
- [minor] site/demo/viewer.js:395-400 — Enter moves focus into the `aria-live` panel, which it also updates, so screen readers may read the content twice — acceptable, but consider dropping `aria-live` updates when focus moves there (optional).
- [minor] (unrelated, from the implementer's note) site/demo/data.json — blame `author` shows the real first name "Raul". It comes from the task 13 exporter, so task 23 should decide whether that name is public.
